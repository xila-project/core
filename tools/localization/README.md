# Localization auditing (issue #442)

Xila uses per-crate `locales/{en,fr}.json` catalogs extracted by
`tolgee.extractor.mjs` and compiled by `embedded-i18n`. Translation
coverage reported by Tolgee is not by itself evidence that every user-facing
literal is internationalized.

## Current audit

| Surface | Findings | Status |
| --- | --- | --- |
| LVGL Settings / shell login | Many labels already use `translate!` | Continue systematic review of dialogs, dynamic labels and overflow |
| Terminal | Input placeholder was hard-coded in English | Translated in this change; UTF-8 width/wrapping still needs UI testing |
| CLI `help` | Built-in/executable section headers and external-executable message were literal English | Translated in this change |
| CLI built-in usage | `executables/shell/command_line/src/commands/mod.rs` and `commands/*.rs` still include hard-coded usage text, some generated by `GetArgs` derive | **Open**: review compatibility and translate human-readable help separately |
| Shell command names, flags, paths, environment variable names, programmatic output | Protocol/CLI interface identifiers, not prose | **Do not translate** |
| Rust errors | Most module `Display` implementations already use `translate!` | Continue reviewing new/changed error paths |
| Browser demo help panel | `examples/wasm/index.html` contains independent English help text | **Open**: choose browser-specific localization / content strategy, avoid pretending Rust catalogs cover it |
| Logs / internal diagnostics | Primarily developer-oriented, may contain fixed English literals | Keep stable unless intentionally made user-facing |

The inventory identifies follow-up areas; it is **not** a claim that the UI
audit or LVGL screenshot/overflow testing is complete.

## Fast catalog checks

```sh
npm ci
npm run check:translations
```

This checks every `**/locales/en.json` namespace and its sibling locale
catalogs. In addition to the existing strict Rust build checks, it rejects:
missing/extra keys, invalid Rust-style brace syntax, and changed placeholder
signatures. Placeholder ordering is intentionally strict: reordering implicit
positional `{}` tokens can silently change message meaning. Explicit
reordering may be supported later with dedicated format-string analysis.

CI runs this once in the English localization matrix entry; the existing
compile-time `EMBEDDED_I18N_STRICT=1` checks still run independently for
English and French.

## Opt-in pseudo-localization

```sh
npm run pseudo:translations
```

Writes expanded, accented catalog fixtures to
`target/pseudo-locales/<namespace>/pseudo.json`, leaving tracked catalogs
untouched. The Node smoke tests exercise representative UI and shell strings,
assert expansion and preserve format placeholders.

**These fixtures are not a runnable Xila locale yet** and should not be
included in a production image. Connecting pseudo strings to an actual LVGL
UI/layout smoke harness (small displays, text truncation, dialogs, terminal
wrapping) remains follow-up work. No runtime mechanism or extra MCU memory
footprint is introduced here.

## Translation conventions

- English is the canonical message key and fallback; retain exact Rust
  placeholders such as `{}`, `{name}` and `{:.2}`.
- Translate prose shown to people, not command names, argument flags,
  protocol fields or scripting contracts.
- Prefer per-crate catalog namespaces over one global catch-all catalog.
- Synchronize changes through [Tolgee](https://translate.anneraud.fr/engage/xila-core/)
  and review translations by a fluent speaker.
- Use `EMBEDDED_I18N_LOCALE=en` or `fr` for compile-time localized builds;
  switching at runtime is out of scope (#444).
